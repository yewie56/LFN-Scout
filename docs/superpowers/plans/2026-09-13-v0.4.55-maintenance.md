# LFN-Scout v0.4.55 Maintenance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Deliver v0.4.55 with the six agreed maintenance changes without changing the Supabase backend implementation.

**Architecture:** Keep existing Android/Compose architecture. Add small pure policies for waterfall statistics and comment timing so behavior is testable. Keep technical Supabase identifiers internally, but user-visible normal-mode strings say Cloud; developer diagnostics may retain technical names.

**Tech Stack:** Kotlin, Jetpack Compose, Android DataStore, MediaStore, JUnit4, Python static verification.

**Spec:** Conversation-approved v0.4.55 requirements dated 2026-09-13.

## Global Constraints

- Version is 0.4.55.
- Normal-mode L50/L90 range is fixed at 2–25 Hz.
- Developer mode may persistently configure the L50/L90 range.
- Rating comment timeouts are 10 s before first edit and 10 s inactivity after every edit.
- Audio comment timeouts are 60 s before first edit and 10 s inactivity after every edit.
- Entering Zusatzfunktionen refreshes the local audio archive automatically.
- Waterfall image save asks before overwriting any existing selected output file.
- User-visible normal-mode wording uses Cloud instead of Supabase; internal class/API/backend identifiers remain unchanged.
- Current debug log can be exported; normal-mode export is user-safe, developer-mode export may retain technical backend wording.
- No Supabase backend/function/schema changes in this release.
